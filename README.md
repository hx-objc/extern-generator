# extern-generator

> **Experimental.** A work in progress, made to find out what the declarations should look like. Expect the output, the rules behind it and the tool itself to change.

Generates Haxe extern declarations of the Apple SDKs' Objective-C and C APIs (macOS, iOS and Mac Catalyst) for [hxmc](https://github.com/benmerckx/hxmc)'s Objective-C interop, from clang's AST of the SDKs' headers, and splits them into the libraries below.

The generator is plain Haxe and builds with hxmc.

## Libraries

A program depends on its platform's library, which brings the shared ones:

| platform | hxmc targets | library | brings |
|---|---|---|---|
| macOS | `macos-arm64`, `macos-x86_64` | [apple-appkit](https://github.com/hx-objc/apple-appkit) | [apple-shared](https://github.com/hx-objc/apple-shared), [apple-shared-mac](https://github.com/hx-objc/apple-shared-mac) |
| iOS | `ios-arm64`, `ios-sim-arm64` | [apple-uikit](https://github.com/hx-objc/apple-uikit) | apple-shared, [apple-shared-uikit](https://github.com/hx-objc/apple-shared-uikit) |
| Mac Catalyst | `macos-catalyst-arm64`, `macos-catalyst-x86_64` | [apple-catalyst](https://github.com/hx-objc/apple-catalyst) | apple-shared, apple-shared-uikit, apple-shared-mac |

A program using only Foundation, Core Graphics or another framework every platform has depends on its platform's library too: Foundation's main classes are not the same on every platform (`NSString` takes AppKit's drawing methods on macOS, UIKit's on iOS), so they are in the platform libraries. A program links only the frameworks whose declarations it uses. How hxmc uses them: [interop.md](https://github.com/benmerckx/hxmc/blob/main/docs/interop.md#the-sdks-declarations).

Optional: [apple-matter](https://github.com/hx-objc/apple-matter) (Matter, the SDKs' largest framework, on every platform) and [apple-appkit-legacy](https://github.com/hx-objc/apple-appkit-legacy) (macOS's frameworks gone in all but name, OpenGL, QuickDraw, Tcl, Ruby, ..., and the classes deprecated as a whole that nothing else names).

Each module is in the library of the platforms where its text is the same (`objc-extern-gen slice`, src/Slice.hx), so a platform's libraries have each type once, and together are the platform's whole output. They refer to each other's types by their paths, without declaring a dependency where they cannot (a shared library on a platform's): a library used without the ones it refers to fails where such a type is used, not before: the shared libraries are not for use on their own.

## Use

macOS with Xcode (clang, the macOS and iOS SDKs) and node:

```sh
npm install
npm run gen                   # builds bin/objc-extern-gen, writes out/ (a few frameworks)
tools/libs.sh out/sdk         # the three platforms, the whole SDKs, and the libraries in out/sdk/libs (27.2.0 from Xcode 27.2)
tools/publish.sh out/sdk/libs # pushes the libraries to their repositories, tagged 27.2.0 (DRY_RUN=1: all but the push)
```

`bin/objc-extern-gen <out-dir> [--frameworks all|Foundation,AppKit,...] [--platform macos|ios|maccatalyst] [--check]` writes a package per framework (`appkit.NSView`, `foundation.NSString`, ...), one module per class or protocol, `skipped.txt` (what was left out and why), `raw.txt` (the parameters left raw memory, `Ptr` and `CString`, by why) and, with `--check`, `ObjcExternsCheck.hx`, a program naming every type. `--frameworks all` is the whole SDK: every framework with an umbrella header that imports on its own and that the platform links (its `.tbd` names the platform: Mac Catalyst links 55 fewer than macOS), `Kerberos` aside (it redefines `GSS`'s types), `CoreHaptics` and `NetworkExtension` imported first (else `AVFAudio`'s `AVAudioSession` and `AccessorySetupKit`'s `ASAccessory` are unavailable to them), AppKit not on Mac Catalyst. A framework inside another (`HIServices`, the Accessibility API, in `ApplicationServices`) is read through its outer framework's header. One in `/System/Library/SubFrameworks` that an umbrella re-exports is the umbrella's (iOS's `ARKitCore`, `ARKitUI` and `ARKitFoundation`: `arkit`, linked as `ARKit`, as on Mac Catalyst, whose ARKit has them itself); another is in scope by its own name. `dispatch`, `os` and `xpc` name libSystem's libraries (GCD, os_log's and os_unfair_lock's functions, XPC). `--platform ios` reads the iOS SDK (arm64) and iOS's availability; `--platform maccatalyst` the macOS SDK with its iOS frameworks (`/System/iOSSupport`) and Mac Catalyst's availability (clang infers it from iOS's), a framework there named as on iOS (hxmc's linker finds its Catalyst build). The dump is read one top-level declaration at a time (an SDK's is gigabytes). `--json` and `--text` read existing dumps instead of running clang; `--keep-dumps` keeps the ones it makes (in `<out-dir>/.clang`).

`bin/objc-extern-gen slice <out-dir> <macos-dir> <ios-dir> <maccatalyst-dir> --version <x.y.z>` writes the libraries, each a haxelib (`haxelib.json`, `src/`) and an npm package that hxmc takes as a library (`package.json`'s `"haxe"` field): `npm install -D github:hx-objc/apple-appkit` and `-lib apple-appkit`, `lix install gh:hx-objc/apple-appkit`, or `haxelib git apple-appkit https://github.com/hx-objc/apple-appkit` (`haxelib.json` names the dependencies by their Git URLs). With npm a project needs no lix scope, whose `.haxerc` makes VS Code's Haxe extension start the compilation server with `--wait stdio`, which Haxe 5, hence hxmc, does not have.

**Releases** ([#4](https://github.com/hx-objc/extern-generator/issues/4)): the libraries are released together, one version per Xcode, its major and minor version and a patch: `27.2.0` from Xcode 27.2, `27.2.1` when the generator changes and the SDK does not (`tools/libs.sh out/sdk 1`). The version is each library's (`haxelib.json`, `package.json`) and its repository's tag, which `tools/publish.sh` makes and refuses to make again; the libraries depend on each other at that tag (`github:hx-objc/apple-shared#27.2.0`, `git:https://github.com/hx-objc/apple-shared.git#27.2.0`), so a program pins one (`npm install -D github:hx-objc/apple-appkit#27.2.0`) and moves to the next SDK's on purpose: a newer SDK refines the types (nullability, generics) as well as adding APIs.

The generated declarations are derived from Apple's headers: they are not part of this repository, and they carry none of the headers' comments.

## Rules

What the declarations make of the headers (decided in [#1](https://github.com/hx-objc/extern-generator/issues/1)):

- **Properties** are `var x(get, set)`. One readonly in a class and readwrite in a subclass (`NSPanel.floatingPanel`) gets only its setter in the subclass (`panel.set_floatingPanel(true)`): Haxe does not let a subclass redefine the variable, and a setter on the superclass would accept calls that fail at run time.
- **Informal protocols**, categories of `NSObject` that name methods for other objects to implement (`controlTextDidChange:`, `validateMenuItem:`), are left out (`skipped.txt` lists them): those outside NSObject's own headers that a formal protocol of their name supersedes, or whose methods all take their sender first (named `sender`, a notification, or an object of the class the selector's first piece names).
- **Availability** ([#4](https://github.com/hx-objc/extern-generator/issues/4)): what the headers introduce after the oldest systems hxmc's programs run on (macOS 10.15, iOS and Mac Catalyst 15.0) is `@:hxmc.available(macos >= 14.0, ios >= 17.0, maccatalyst >= 17.0)`, conditions as `#if` writes them (a version with a patch level is `version("10.15.4")`), on classes, protocols, methods, properties (the variable and its accessors), C functions and variables and enum constants, for hxmc to check a use against the deployment target (`if (hxmc.Platform.supports(link.setPreferredFrameRateRange)) ...`; `#if (macos >= 14.0)` for a version alone). It names every platform the headers give a version for, whichever is generated (Mac Catalyst's is iOS's where the headers give none, as clang infers it), so that a declaration's text is the same on each and its module stays in the shared library. A member's is its own and its class's, protocol's or category's, the later version of each platform (a class's redeclared `alloc` and initializers take the class's), as nothing is inherited from the class in the output.
- **Names**: enum constants lose their common prefix (`NSWindowStyleMask.Titled`); types are non-null unless `_Nullable`. Methods whose selectors begin alike are `overload`s of the first piece where their parameters' types differ (`systemFontOfSize(size)`, `systemFontOfSize(size, weight)`), the others named by their pieces joined. `@:deprecated` carries no message. A type's name starts upper case (`gssapi.h`'s constants are `GssapiConstants`, vImage's `vImageConverterRef` `VImageConverter`); of two in a package whose names differ only in case (Matter's `MTRBaseClusterOTASoftwareUpdateProvider` and its deprecated `...Ota...`), one file where file names ignore case, the deprecated one goes and references to it name the other.
- **Protocols** are extern interfaces (`@:hxmc.objc("Name")`, extending the protocols they adopt), named `NameProtocol` when a class has the name (`NSObjectProtocol`). Optional members are `@:optional`: a Haxe class implementing the protocol may leave them out, and Objective-C then sees no such method. A protocol's methods are never overloads (a Haxe class implementing one declares none): a method keeps its selector's first piece when no other method of the protocol's family begins with it (or it is that piece alone), else its pieces are joined (`parserFoundCharacters` for `parser:foundCharacters:`). `id<P>` is `P`. A class implements the protocols it adopts, under the protocols' names (a method the class names otherwise gets a field of the protocol's name too, sending the same selector); one whose names the class gives other members is left out (`skipped.txt`). Which methods are `@optional` is read from the protocol's header, which clang's dumps do not tell. A protocol's class members (`+supportsSecureCoding`, `+readableTypesForPasteboard:`) are statics of its interface, which Haxe allows in extern interfaces: a Haxe class conforming implements them as its own statics (hxmc registers those on its metaclass).
- **Lightweight generics** are type parameters bound to `hxmc.objc.Id` (any object, which the root classes and protocols extend) and defaulting to it: `NSArray<ObjectType:Id = Id>`, `NSArray<NSString *> *` is `NSArray<NSString>`, a bare `NSArray *` `NSArray<Id>`. A superclass's arguments are read from the declaration (`NSLayoutXAxisAnchor extends NSLayoutAnchor<NSLayoutXAxisAnchor>`). A static method declares the class's parameters it uses (`alloc<ObjectType:Id>()`). Haxe's parameters are invariant: a covariant class (the immutable collections) has `upcast`, widening its elements to a supertype (`NSArray.upcast(subviews):NSArray<NSObject>`).
- **Options** (`NS_OPTIONS`) are enum abstracts with `|` and `&`, `None` (no bits) and `has` (all the given bits set: `o.has(WithoutChanges)`).
- **Haxe values where Cocoa takes `NSString` or `NSNumber`**: a parameter or property of either type is `foundation.NSStringArg` or `NSNumberArg`, an abstract over it (`@:forward`, from and to it) that converts a Haxe `String` (an autoreleased copy), or an `Int`, `Float` or `Bool`, by `@:from`: `field.placeholderString = "Search"`, `formatter.multiplier = 100`. Results stay `NSString` and `NSNumber`. Properties are typed as their setters take them, as Haxe allows a property one type; protocols alike, as the classes implementing them must match. Collections are not converted.
- **Constants of the headers** (`static const NSInteger NSNotFound = NSIntegerMax;`, `NSControlStateValueOn`): as constant macros, their initializers evaluated.
- **Constant macros** (`#define kVK_Space 0x31`, `#define kAXTitleAttribute CFSTR("AXTitle")`, `((CGWindowLevel)20)`, expressions of other constants) are constants of their header's constants class, with the anonymous enums' (`hitoolbox.EventsConstants.kVK_Space`): `Int`, `hxmc.I64` or `Float`, and an `NSString` for `CFSTR` and `@"..."`, made when first used. A macro of anything else (attributes, calls, C strings) is left out (`skipped.txt`). The preprocessor's output is read (`clang -E -dD`), its line markers telling each macro's header.
- **Function pointers** a C function takes are typed callbacks, the function's type as C passes it (`AudioHardwareRemovePropertyListener(id, inProc:(Int, Ptr) -> Int)`), a static `@:hxmc.callback` function passed by name; a nullable one stays `Ptr` (a typed callback is never NULL), as do those a message takes or a struct holds (`hxmc.unsafe.Callback.addr` goes there).
- **Packages**: one per framework; Core Graphics' types (`CGRect`, `CGPoint`, `CGSize`, ...) are in `coregraphics`.
- **Types**: `id` is `hxmc.objc.Id` (any object: messages to it need a cast or `Std.downcast` first), `id<P>` `P`, `Class` `hxmc.objc.ObjCClass` (a class object: `ObjCClass.of(C)`). Core Foundation's `Boolean` is `Bool`. `const char *` is `hxmc.unsafe.CString`, other pointers `Ptr`, but where a C function's parameters take hxmc's safe forms (below). A block is a Haxe function (`completionHandler:(Null<NSData>, Null<NSURLResponse>, Null<NSError>) -> Void`), a block taking or returning blocks too (`performAsynchronousFileAccessUsingBlock(block:(() -> Void) -> Void)`), `Null<...>` when `_Nullable`.
- **Objects of C** (Core Foundation's types and those built like them: `CGColorRef`, `CGPathRef`): an extern class implementing `hxmc.objc.Id`, named after its `…Ref` typedef, for each struct the headers bridge to Objective-C (`CF_BRIDGED_TYPE`); a non-`const` typedef of a `const` one's struct is its subclass (`CGMutablePath extends CGPath`). A struct bridged toll-free to a class is that class (`CFStringRef` is `NSString`, `CTFontRef` `NSFont`, `CFMutableArrayRef` `NSMutableArray`); `CFTypeRef` is `Id`.
- **C functions and variables** of the frameworks in scope are static fields of one class per framework, under their C names (`coregraphics.CoreGraphics.CGColorCreate`, `appkit.AppKit.NSFontAttributeName`): `using coregraphics.CoreGraphics;` makes them methods of their first argument (`ctx.CGContextFillRect(r)`). A function returning an object the caller owns is `@:hxmc.retained`: C's object by Core Foundation's Create rule (`Create` or `Copy` in its name, in a region the headers audit) or `CF_RETURNS_RETAINED`, an Objective-C object by `NS_RETURNS_RETAINED` only (ARC's rule); a function returning C's object outside an audited region is left out. Left out too: functions only in their headers (`static inline`: `CGRectMake`, no symbol), reference counting (`CFRetain`, `CGColorRelease`: the compiler's) and variadic ones. A block a C function takes or returns is `hxmc.objc.Block<F>` (converted from and to a function `F` where it is passed: `path.CGPathApplyWithBlock(e -> ...)`). A variable `const` at its top level, or holding an object, is `final`.
- **Safe C calls**: a C function's parameters take hxmc's typed forms where the headers tell enough, so that calling it is no raw memory (no `@:hxmc.unsafe`). A pointer to a scalar or a struct is a span (`ReadOnlySpan` when `const`) whose length `@:hxmc.len` gives: another parameter by clang's bounds attributes (`__counted_by(n)`, `__sized_by(n)` over bytes) or by `Lengths.hx` (the pairs of the frameworks' common functions the headers do not annotate: `CGContextFillRects(c, rects:ReadOnlySpan<CGRect>, count)`, `CTFontGetGlyphsForCharacters`), a constant by an array's size (`const CGFloat whitePoint[3]`) or `__single`, else one element where nothing says otherwise: a struct (`const CGAffineTransform *`) or a scalar written wider than a byte (`CGFloat *ascent`, an out-parameter: `CTLineGetTypographicBounds(line, Span.of(ascent), Span.of(descent), Span.of(leading))`), in a function taking no length, not named for many (`displays`, `outPacketDescriptions`), not a pointer type of its own (`AudioQueueBufferRef`, whose address matters). An optional input (`const T * _Nullable`) stays `Ptr`, as NULL says what no value does, unless `Lengths.hx` gives its length (a transform's NULL is the identity). A `const char *` is a `String` (and a `const char *` result one, borrowed) in a function that can be `@:hxmc.safe`: one taking nothing but scalars, structs, spans and callbacks, whose result is no string pointing into an argument. Spans of one come from GC code as `Span.of(x)` and `ReadOnlySpan.of(v)`; longer ones from kernels (GC code lends only bytes: `Span.ofBuffer`). What stays raw, and why, is in `raw.txt`: messages (hxmc's messages take no String, span, out-parameter nor typed callback: `NSError **` is `Ptr`), opaque handles (`AUGraph`), `void *`, objects written back (`CFErrorRef *`), arrays of a length no parameter gives (`CTRunGetGlyphs`'s, by a `CFRange`), pointer results.
- **Trusted code in the declarations**: what the declarations themselves do with raw memory (`NSStringArg`'s conversion, `CFSTR` constants, a struct's constructor storing a `Ptr` field) is `@:hxmc.unsafe`, so they build without warnings under hxmc's raw-memory rule (`-D hxmc.strict`).
- **Variadic methods**: a nil-terminated list of objects (`NS_REQUIRES_NIL_TERMINATION`: `arrayWithObjects:`, `dictionaryWithObjectsAndKeys:`) is its named parameters and `...rest` of the first one's type, `@:hxmc.nilTerminated` (`NSArray.arrayWithObjects(a, b, c)`; an overload beside `arrayWithObjects:count:`). Format methods (`stringWithFormat:`, `predicateWithFormat:`) and mixed lists are left out: format in Haxe, or use the non-variadic sibling (`predicateWithFormat:argumentArray:`).
- **Redeclarations**: a class redeclares `alloc` and the initializers it inherits for their result's type; not `self`, `new` or `allocWithZone:`. `retain`, `release` and `autorelease` are left out (memory is the compiler's).
